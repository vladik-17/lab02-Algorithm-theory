# Энергокалькулятор

Лабораторная работа №2, вариант 12 «Бытовая техника».
Планируемая сложность — Well-done.

Приложение рассчитывает потребление электроэнергии и стоимость
работы утюга, телевизора, стиральной машины, чайника и микроволновки
за заданный период. Первые три прибора обязательны по варианту задания.

## Текущее состояние

Сейчас добавлены точка входа `main.py`, пакет `energy_calculator`,
список зависимостей, Dockerfile и конфигурация Docker Compose. Интерфейс — отдельное окно
на Tkinter, которое можно растягивать, с кнопкой «Справка».
Добавлен модуль `energy_calculator/appliances.py`: абстрактный класс
`Appliance` и пять классов приборов. Мощность проверяется через `property`:
допускаются только конечные числа больше нуля. Каждый класс явно
определяет два dunder-метода: `__init__` и `__str__`.
Модуль `energy_calculator/calculations.py` выполняет расчёт. В окне можно
выбрать прибор, изменить мощность, часы работы в день, количество дней
и тариф. Выбор другого прибора подставляет его начальную мощность.
При изменении данных предыдущий результат сбрасывается.
Третий модуль `energy_calculator/storage.py` сохраняет успешные расчёты
в SQLite и экспортирует всю историю в Excel. Числа в базе хранятся
текстом, чтобы сохранить точность `Decimal`.

Начальные мощности — примеры, их можно менять:

| Прибор | Мощность, Вт |
| --- | ---: |
| Утюг | 2000 |
| Телевизор | 100 |
| Стиральная машина | 1800 |
| Чайник | 2000 |
| Микроволновка | 1200 |

Для своего прибора используйте потребляемую мощность с его шильдика
или из инструкции. Для микроволновки нужна потребляемая мощность,
а не выходная мощность нагрева.

## Запуск

Нужен Python 3.13 с Tkinter (в стандартной установке Python для Windows
этот компонент обычно включён). Из папки проекта:

```powershell
python -m pip install -r requirements.txt
python main.py
```

Откроется окно «Энергокалькулятор». Проверьте изменение размеров и кнопку
«Справка». Для экспорта используется `openpyxl`, для тестов — `pytest`.

## Краткая справка

1. Выберите прибор и проверьте его мощность в ваттах.
2. Укажите часы работы в день от 0 до 24, целое количество дней от 1
   и неотрицательный тариф в рублях за кВт·ч.
3. Нажмите «Рассчитать» или Enter. Можно использовать точку или запятую
   в дробных числах. При неверном вводе под формой появится сообщение.
4. Каждый успешный расчёт автоматически сохраняется. Во вкладке «История»
   находятся все записи, начиная с последней. Повторное нажатие «Рассчитать»
   создаёт новую запись, даже если параметры не менялись.
5. Во вкладке «История» нажмите «Экспорт в Excel» и выберите место сохранения
   файла `.xlsx`. Экспортируется вся история с датами, исходными параметрами
   и результатами. При пустой истории программа предложит сначала выполнить расчёт.

История хранится в `data/history.db` рядом с `main.py` и остаётся после закрытия
программы. Путь не зависит от папки, из которой запущен Python. Каталог `data/`
исключён из Git; для переноса истории на другой компьютер нужно отдельно
скопировать базу. В таблице есть горизонтальная и вертикальная прокрутка.
Ширина столбцов автоматически подбирается по заголовкам и записям после
обновления истории. Столбцы не растягиваются на всё окно без необходимости.
Нажатие заголовка сортирует записи по этому столбцу, повторное нажатие меняет
направление. Числа сортируются по значению, даты — по времени, названия —
по алфавиту. Стрелка в заголовке показывает порядок. Выбранная сортировка
сохраняется при добавлении расчётов в текущем сеансе. При новом запуске
сначала показываются последние записи. Строки имеют чередующийся фон.
Сортировка относится к таблице: в Excel записи по-прежнему идут от новых к старым.
Экспорт содержит сохранённые результаты, а не формулы: изменение ячеек Excel
не пересчитывает историю. Денежные значения выводятся с двумя знаками.

Энергия (кВт·ч) = мощность (Вт) / 1000 × часы в день × дни.
Стоимость (руб.) = энергия (кВт·ч) × тариф (руб./кВт·ч).
Стоимость округляется до копеек по правилу: половина копейки вверх.
В расчётах используется `Decimal`, результат энергии в окне выводится
с четырьмя знаками после запятой.

Контрольный пример: утюг 2000 Вт, 1 час в день, 30 дней, тариф 6 руб./кВт·ч.
Результат — **60 кВт·ч и 360 руб.** Тариф 6 — пример, а не актуальная цена.
Модель предполагает постоянную мощность в течение указанного времени;
фактическое потребление зависит от режима работы и циклов нагревателя.

## Проверка

```powershell
python -m pip install -r requirements.txt
python -m pytest -v
```

Тесты проверяют формулы, округление, дробный ввод с запятой, нулевое
время и тариф, ошибки ввода и общие требования к пяти классам приборов.
Также проверяются сохранение всех параметров, повторное открытие базы,
выгрузка всей истории, числовые ячейки Excel, пустая история и ошибка записи.
Тестовые базы создаются во временных папках и не затрагивают историю приложения.
Для ручной проверки: смените прибор, выполните контрольный пример,
попробуйте ввести 25 часов в день, измените размер окна и откройте справку.

## Docker

Запуск на Windows 11 использует Docker Desktop с Linux-контейнерами,
WSL 2 и доступным графическим сервером WSLg. Приложение открывается
отдельным окном. Браузер и дополнительная установка Python на Windows
для контейнерного запуска не нужны.

1. Запустите Docker Desktop и дождитесь готовности движка.
2. Откройте PowerShell в папке проекта и выполните:

```powershell
docker compose up --build
```

При первой сборке нужен интернет: загружается базовый образ Python 3.13,
библиотеки Tk, шрифты с кириллицей и зависимости из `requirements.txt`.
Зависимости устанавливаются при сборке, до запуска приложения.
Повторный запуск готового образа:

```powershell
docker compose up
```

Закрытие окна завершает программу. Для остановки из другого терминала:

```powershell
docker compose down
```

Папки `data` и `exports` подключаются с компьютера в `/app/data` и
`/app/exports`. Поэтому база остаётся после удаления контейнера.
При экспорте диалог по умолчанию открывает `/app/exports`: сохранённый туда
Excel-файл появится в папке `exports` проекта на Windows. Выбирайте эту
папку, чтобы файл оставался доступен после удаления контейнера.

Тесты в том же образе, без запуска окна:

```powershell
docker run --rm lab02-energy python -m pytest -v
```

В `compose.yaml` графический сокет подключается из
`/mnt/host/wslg/.X11-unix`, значение `DISPLAY` — `:0`. Путь соответствует
WSLg в Docker Desktop на проверяемом компьютере. Если в другом окружении
сокет расположен иначе, задайте переменную `WSLG_SOCKET_DIR` перед запуском.
Если появляется ошибка `couldn't connect to display`, проверьте наличие
WSLg и сокета `X0`; один Docker Desktop без доступного графического сервера
не обеспечивает показ окна. Порты в сеть не публикуются.

Способ подключения X11 описан в [документации Microsoft WSLg](https://github.com/microsoft/wslg/blob/main/samples/container/Containers.md).

Проверено на рабочем компьютере: образ успешно собирается, окно открывается
через WSLg, все 37 тестов проходят внутри контейнера. Контрольный расчёт
сохраняется в общей базе; после `docker compose down` и повторного запуска
история остаётся. Экспорт из контейнера доступен в папке `exports` на Windows.
Снимки приложения и результатов тестов находятся в `docs/screenshots`.
