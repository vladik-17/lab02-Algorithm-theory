# Энергокалькулятор

Лабораторная работа №2, вариант 12 «Бытовая техника».
Планируемая сложность — Well-done.

Приложение будет рассчитывать потребление электроэнергии и стоимость
работы утюга, телевизора, стиральной машины, чайника и микроволновки
за заданный период. Первые три прибора обязательны по варианту задания.

## Текущее состояние

Сейчас добавлены точка входа `main.py`, пакет `energy_calculator`,
список зависимостей и черновик Dockerfile. Интерфейс — отдельное окно
на Tkinter, которое можно растягивать, с кнопкой «Справка».
Добавлен модуль `energy_calculator/appliances.py`: абстрактный класс
`Appliance` и пять классов приборов. Мощность проверяется через `property`:
допускаются только конечные числа больше нуля. Каждый класс явно
определяет два dunder-метода: `__init__` и `__str__`.
Расчётов пока нет; классы ещё не подключены к окну.

Начальные мощности — примеры, их можно менять:

| Прибор | Мощность, Вт |
| --- | ---: |
| Утюг | 2000 |
| Телевизор | 100 |
| Стиральная машина | 1800 |
| Чайник | 2000 |
| Микроволновка | 1200 |

Для своего прибора используйте потребляемую мощность с его шильдика
или из инструкции. Для микроволновки нужна потребляемая мощность,
а не выходная мощность нагрева.

## Запуск

Нужен Python 3.13 с Tkinter (в стандартной установке Python для Windows
этот компонент обычно включён). Из папки проекта:

```powershell
python main.py
```

Откроется окно «Энергокалькулятор». Проверьте изменение размеров и кнопку
«Справка». Дополнительных библиотек на этом этапе нет.

## Docker

Dockerfile пока является заготовкой. Для запуска графического окна
из Linux-контейнера на Windows потребуется настройка вывода изображения
и библиотек Tk. Это будет отдельный этап; текущий Dockerfile ещё
не обеспечивает запуск окна. Зависимости Python будут устанавливаться
из `requirements.txt` при сборке образа.

## Запланированные функции

- Форма расчёта с понятными подписями, адаптацией к размеру окна и справкой.
- Расчёт энергии и стоимости с проверкой введённых данных.
- История расчётов в SQLite и экспорт в Excel.
- Три рабочих модуля пакета, классы и требования ООП из задания.
- Тесты pytest, UML и отчёт со скриншотами.

Функции добавляются небольшими этапами после проверки предыдущего.
Коммиты и отправку в GitHub выполняет автор проекта.
